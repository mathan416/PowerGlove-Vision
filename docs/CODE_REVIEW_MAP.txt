CURRENT SYSTEM
--------------
The PowerGlove Vision Controller (Arduino UNO Q) captures the newest camera
frame, runs MediaPipe Hands with the selected four-thread CPU baseline, applies
player calibration and gesture settings,
and transmits authenticated controller state. RetroPie publishes a virtual
PowerGlove Vision gamepad and the latest native state. Neither path queues old
movement samples. Latest coordinate is the native X/Y default and guards only
one contradictory or unusually distant non-forward result after a brief loss;
ordinary tracking and strongly aligned forward recovery remain direct. FCEUmm handles standard mappings and remains the explicit
Super Glove Ball fallback. lr-nestopia-powerglove supports native Super Glove
Ball; a completed live game confirmed Start, continuous X/Y, release/throw,
grab/catch, index-point fire, and fist-plus-forward Power Punch. Unused fields
remain deliberately neutral. Latency and stationary jitter still need the
planned external hand-and-screen recording; no measured improvement is claimed.

The shared website provides Dashboard, local Rock Paper Scissors at /play,
sixteen Glove Academy lessons and personalization at /learn, Help, and /setup.
Setup contains status markers, attract settings, connection/startup, guided
pairing, and Games. Dashboard owns arming and power controls. Pairing supports
one-time codes and SSH passwords, requires physical certificate/PIN confirmation,
and releases its matrix display when the submitted transport attempt finishes.
Idle display then follows On, Dim, or Off. Networking includes Wi-Fi and Ethernet.
Setup uses its plain URL and the shared favicon, without a page-revision redirect.

TRACE THE RUNTIME
-----------------
python/main.py supervises the application, matrix, and worker lifecycle.
src/powerglove_vision/control_server.py owns the always-available HTTP/HTTPS API.
web_common.py, setup_web.py, player_web.py, academy_web.py, statistics_web.py,
and help_content.py provide the shared page shell, Setup, players, optional
browser-local statistics, Academy, and built-in guides.
tracker.py -> gesture.py -> vision_app.py connects capture to recognized input.
transport.py -> receiver.py -> native_state.py connects authenticated input to
RetroPie gamepad/native publication. native/nestopia-powerglove holds the core
patch and deterministic tracing material. pairing.py and python/ssh_pair.py
handle the two provisioning methods; matrix.py handles physical PIN display.
retropie_hook.py and profile_control.py handle registered-game launch selection.
players.py and configuration references explain per-player hand state.
Read the matching tests beside each implementation. Preserve personal data,
credential handling, newest-frame/state-only behavior, and explicit fallbacks.

DOCUMENTATION AND DELIVERY
--------------------------
Help renders maintained Markdown through help_content.py. Overlapping Markdown
has been consolidated into 19 owning documents. The PDF editions intentionally
remain at their pre-consolidation state until the next requested regeneration;
scripts/build-docs-pdf.py will remove superseded editions at that time.
Keep intentional extra-finger artwork and its published count synchronized.
Community guides cover building the hardware, native emulation, and symptom-led
troubleshooting. Documentation screenshots use simulated, non-secret fixtures;
tests/browser_setup_pairing.py --screenshots regenerates the guided Setup images.
scripts/application-payload.py selects public deployment files; installation
manifests preserve device-owned settings and detect local source modifications.
The cabinet-specific quick reference and this review map are not public payloads.

VALIDATION
----------
Latest runtime checks: 496 unit tests run, one expected Linux-specific skip;
browser interaction checks include pairing, Academy, camera-rate, and optional
statistics behavior. Coverage includes delayed clicks, progress/errors, both methods,
expiry/retry, duplicate requests, matrix completion cleanup, and plain/old Setup
URLs. The user confirmed successful live pairing and the subsequent matrix/URL
fix. This does not replace fresh-device installation or physical latency tests.
Before publishing, run the source/documentation audits, syntax checks, and the
relevant tests listed in docs/CONTRIBUTING.md. Do not publish private runtime
state, tokens, passwords, active pairing codes, or raw camera recordings.
